ログイン経路の整理と真因

先方社屋でログインできなかった件の調査記録。原因はコードではなく、アプリを開く URL でした。あわせて確定したログイン 3 経路の条件と、今日修正した不具合をまとめます。

01真因

WOFF アプリは専用の「WOFF URL」から開かないと認証できない。 サイト URL（orec-demo-app.suncac.net）を LINE WORKS アプリ内ブラウザで直接開いても、WOFF セッションが確立されないため必ず失敗します。

当初はテナントの違いや実装漏れを疑いましたが、いずれも誤りでした。同じ端末・同じアカウントで、WOFF URL から開けば成功し、サイト URL から開けば失敗します。差は URL だけです。

なぜ URL で変わるのか

実際に出るエラー

Need access_token for api call, Please login first

このエラーはテナントに関係なく、WOFF URL を経由していないすべての環境で発生します。当社テナント・当社アカウント・当社の PC でも同じです。

02ログイン 3 経路

本番環境で実測した結果です。検証済 は実際にログイン完了まで確認したものを指します。

OIDC
推奨		 条件なし。サイト URL から開けばよい 検証済 検証済 検証済
WOFF LINE WORKS アプリ内 かつ WOFF URL から開く 不可 不可 検証済

OIDC を推奨する理由

  • 全環境で動く。 WOFF が動く場面は OIDC でも動きますが、逆は成立しません。
  • 案内する URL が 1 つで済む。 WOFF URL の配布・管理が不要になり、今日と同じ事故が起きません。
  • Bot 通知の宛先も取れる。 id_token の sub は WOFF の userId と同じ LINE WORKS ユーザー ID です。users.woff_id に保存する対応を入れました。
  • 先方展開が軽い。 WOFF アプリの登録ではなく ClientApp 1 つで足りる見込みです（検証中）。

WOFF が必須になるのは、アプリ内 UI 連携（Scan QR、アプリ内ウィンドウ制御など）を使う場合だけです。Bot からのトークルーム通知はサーバー側 API の機能なので、WOFF の有無とは無関係です。

03今日修正した不具合

真因の調査中に見つかったものを含みます。すべて本番に反映済みです。

不具合症状対応
OIDC が無効 503 OIDC is not configured。環境変数が未設定で、フロントに入口ボタンも無かった docker-compose.yml で既存の LINE_WORKS_* を OIDC_* に渡し、ログイン画面にボタンを追加
expires_in の型 トークン交換で cannot unmarshal string into Go struct field 数値・文字列の両方を受ける FlexInt 型を追加
API スコープ不足 FORBIDDEN / has not permission api scope users/me を呼ばず id_token のクレームから読むよう変更。追加権限が不要になった
再ログインで 500 照合が auth_provider = 'local' 限定で、2 回目以降ユーザーが見つからず再作成 → UNIQUE 制約違反 GetOIDCUserByEmail を追加
localhost へ戻る 認証後 http://localhost:5173 にリダイレクト FRONTEND_URL を設定
セッションが切れる ID/PASSWORD でログインしても再読み込みでログアウト（復元処理が woff.init() の中にあった） WOFF の成否と切り離した
デプロイが反映されない index.html に Cache-Control が無く、古い画面が表示され続ける no-store を付与。ハッシュ付き assets は長期キャッシュに
Bot 宛先の欠落 OIDC の sub を保存しておらず、Bot 通知の宛先が分からない users.woff_id に保存。既存ユーザーは次回ログインで補完

04先方への確認と残作業

検証を依頼中

先方に、自社の LINE WORKS アカウントで OIDC ログインを試してもらっています。テナント制約の有無がこれで確定します。

結果意味対応
成功 テナント制約なし 先方での登録は不要。OIDC 一本で完結。WOFF ボタンを撤去する
失敗 テナント制約あり 先方テナントでの ClientApp 登録を依頼。WOFF URL 配布も選択肢に残す

検証で先方のアカウントがこちらの DB に作成されます（表示名とメールアドレス、部署は未設定）。不要になれば管理画面から削除できます。

未対応の課題

  • トークンが URL クエリに載る。 OIDC コールバックが ?token= でフロントに渡すため、nginx と Cloudflare のアクセスログに JWT が記録されます。ブラウザ履歴からは除去済みですが、本来は httpOnly Cookie で渡すべきところです。認証フロー全体の作り替えになるため未着手。
  • WOFF と OIDC で同一人物のレコードが二重化する。 WOFF は woff_id、OIDC は email で照合しており別ユーザーとして扱われます。OIDC 一本に統一すれば発生しません。
  • WOFF ボタンの去就。 先方の検証結果を待って判断します。撤去する場合もコードと API は残し、入口だけ外す方針です。
